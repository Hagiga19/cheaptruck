# Docs Context

## Purpose

Use this folder for project-wide support material that helps future sessions continue CheapTruck without loading every domain file.

Docs should summarize current state, next steps, broad risks, technical research, and useful commands. Product rules still belong in the folder that owns them.

## Owns

- Session continuity notes
- Project-wide next steps
- Broad technical research notes
- Risk and compliance tracking
- Lightweight workspace commands
- Cross-project summaries that do not belong to one product domain

## Does Not Own

- Domain-specific product rules
- Selected implementation architecture, database, storage, containers, deployment, and build notes, which belong in `tech/`
- Durable decisions
- Marketplace listing facts
- Measurements, fit results, prices, availability, or seller responses
- Revenue planning

## Files

- `next-steps.md` - current focus and ordered planning queue
- `session-log.md` - compact history of planning sessions
- `risk-and-compliance.md` - broad risk register and pre-implementation checks
- `technical-research.md` - project-wide technical unknowns and research queue before a direction moves into `tech/`
- `commands-cheatsheet.md` - quick local commands for future Codex sessions

## Rules

- Keep project-wide docs concise and route back to the owning folder when detail belongs there.
- Mark unknowns clearly.
- Do not duplicate domain files just to make one big spec.
- Add verified technical sources only when they affect multiple product areas.
- Update `next-steps.md` when the current planning focus changes.

## Status

Active support area. Current docs are tuned for the planning stage before implementation or revenue work.
