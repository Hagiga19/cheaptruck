# UI Context

## Purpose

Use this folder for every user-facing screen, interface object, interaction, and explanation of why each feature is needed.

The UI starts with the actual room-design workflow. It presents information owned by the other product areas without becoming the source of truth for that information.

## Owns

- Screen layout and navigation
- Inputs, controls, previews, and user-facing states
- How requests, measurements, designs, listings, and updates are presented
- The user need served by each visible feature

## Does Not Own

- Request meaning or validation rules
- Fit calculations
- Marketplace listing facts
- Design-generation rules
- End-to-end system states

## Files

- `interface-map.md` - screens and their responsibilities
- `feature-inventory.md` - visible features and why users need them
- `room-creation-flow-notes.md` - written notes extracted from the Excalidraw room creation sketch
- `app UI design.excalidraw` - visual source sketch for the room creation process
